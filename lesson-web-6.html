3 · Read & play

The debugging loop

Every bug session is the same loop. Symptom: state precisely what's wrong ("the button does nothing when clicked" beats "it's broken"). Hypothesis: list what could cause that. Experiment: the smallest test that confirms or kills the top hypothesis. Fix, re-run, and if the symptom's still there — loop again with what you learned.

The multiplier is isolation: shrink the territory where the bug can hide. Replace a fancy CSS rule with background: red — if red shows, the selector works and the property was wrong. Comment out half the script — if the bug persists, it lives in the other half. Ten seconds per experiment, half the haystack gone each time.

Use the AI as a hypothesis engine, not an oracle: paste the exact error and ask for three ranked hypotheses. You run the experiments. That division of labor keeps you the detective — and detectives learn; oracles' customers don't.

4 · Do it

The bug hunt

1. Ask your AI: "create a single-file HTML page with a button, styles, and a script — then secretly plant three bugs in it: one HTML, one CSS, one JavaScript. Don't tell me what they are."

2. Hunt all three with the loop. Write down each: symptom → hypothesis → experiment → fix.

3. Trade planted-bug pages with a classmate if you can — hunting a human's bugs is even better sport.
