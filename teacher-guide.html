For the teacher

Teacher guide

What the platform does, what it doesn't, what to collect from each lesson, and what good work looks like.

How the platform works

Each lesson is a scroll-through sequence: watch → listen → read → an activity or notebook → a quick check → a build. Students mark segments complete; the quick check completes itself when every question is answered correctly. The build is the graded artifact — every lesson names its turn-in explicitly.

Honest limits, so you can plan around them: progress lives in the student's browser (no accounts, no central gradebook — if they switch devices, the progress bar resets, though their turn-ins don't). Completion evidence is the turn-in stream you collect, not the progress bar. Audio narration is machine-generated for now; Course 1's videos are generated slide videos with the same narration voice. Course 3 notebooks are downloaded and uploaded to Colab (30-second flow, instructions on each lesson page) until the course is published on GitHub, which makes them one-click.

Pacing

A lesson is 2–4 hours of real effort, most of it in the activity and the build. A focused student finishes one per week; one every two weeks still completes a course in a semester. Both paces are printed on every course page as legitimate. The completion event worth celebrating publicly is the lesson finish — weekly wins for the locked-in, biweekly for everyone else.

Course 1 — How AI Works: turn-ins and rubric

LessonTurn-inGood looks likeDiscussion spark
1Half-page explanation of what an LLM does, written for family, plus the first question the family member asked.Mechanism right (prediction, no database), zero jargon. The family question is real, not invented.Collect the family questions on the board — they preview the whole course.
2Three engineered failures with two-sentence explanations.Explanations use token and context window correctly; at least one failure survived the "newer models pass strawberry" escalation.Who found a failure nobody else found?
3Five limits the AI admitted about itself + the one the student will verify.Limits are specific (cutoff date, no personal data, uncertainty) — not vague ("it's not perfect").Did anyone's model claim a different cutoff? Why might that be?
4Bad/good/great prompt experiment with all three outputs.Round 3 pulls all four levers, and the student names which lever moved the result most.Vote: which lever matters most? (There's no right answer — that's the point.)
5Five-round iteration transcript + caption.Rounds show real coaching (not "make it better" ×4); final beats first unmistakably.Read one round-1 and round-5 pair aloud, unattributed.
6Ten-claim report card with verdicts and ≥3 sources.Verification is real (sources named); any caught fake is quoted exactly. "All ten held" is acceptable WITH the escalation run.Tally the class catch-rate — it's your live hallucination statistic.
7Personal AI-use policy + bias tally.Policy is specific and first-person; school rule cited accurately. Tally has real counts.Pool all tallies — 20 students × 5 runs is the sample that actually shows patterns (or shows the mitigation working; both are findings).
8Capstone: one-page "How I use AI" guide + revised policy.All five required elements present, in the student's own voice; the policy revision names what changed and why.What did the course change your mind about? (The capstone is the course grade.)

Course 5 — Build with LLMs: turn-ins and rubric

Before this course starts, you need an API key plan: one class key (simplest: teacher pastes it per session via the getpass cell — students never see it written), a spending cap set at the provider, and the model id you want the class using set in each notebook's MODEL cell. Budget rough order: student exercises use a few hundred tokens per call; a student-lesson is typically well under $1 at current pricing, but set the cap and watch the first week. The notebooks print token usage on purpose — make reading it a habit.

LessonTurn-inGood looks like
1ask() + three answers with token counts.Key handled via getpass only; stop_reason checked; counts actually read.
2System prompt + tool + three outputs.The system prompt has explicit limits; the tool serves a real weekly task.
3events.json + a parse-failure story.Retry pattern present and capped; the failure narrated, not hidden.
4ask_doc() + the refusal screenshot.Both trust rules enforced; tested with a question NOT in the document.
5Chatbot: system prompt, best exchange, token counts.Memory proven (name test); the 20-message guard fires.
6Eval table + shipping decision.Fixed inputs; ≥3 checks incl. their own; the number decided, not the vibe.
7Agent call logs, both demos.The model's decision visible in the log; the can't-help case handled honestly.
8Capstone helper + honesty note, read aloud.All four requirements; the honesty note is specific, not humble-vague.

Course 6 — Think with AI: turn-ins and rubric

LessonTurn-inWhat "good" looks likeWatch for
1Ten real tasks sorted into delegate / collaborate / never, with reasons for every "never."The reasons show the two tests (checkable? carries my name?) actually applied — not vibes.Everything sorted "collaborate" as a hedge. Push for commitments.
2One answer improved three ways (steer / example / restart), transcripts included.The steering message contains specifics; the verdict on which move won cites evidence from the outputs."Make it better" used as the steer — that's the thing the lesson exists to replace.
3A real tutor session log: prompt used, misses, and what was done about each miss.All five tutor settings present, notes pasted in, and the misses led somewhere.Sessions run without "only my notes" — invented facts may be in the log as if true.
4Original paragraph + AI critique + the student's own revision + one-line disclosure.The revision is recognizably the same writer, improved; zero AI-written sentences in it.Revisions that are the ghostwritten text lightly edited. Read the original first, then the revision.
5An AI research brief with every claim marked safe / check-it and real sources for three checked claims.The checked set includes every number, name, date, and quote — and at least one claim died in verification.Briefs where everything survived checking. Either the topic was too safe or the checking was too polite.
6A dated plan for a real multi-week obligation, plus which splits the AI got wrong and the student fixed.Every task fits one sitting with a visible finish; at least one AI-proposed step was pushed back on.Plans accepted verbatim from the AI. The fixes ARE the evidence of learning.
7The personal prompt file: three templates with slots marked and a when-to-use line each.At least one template is the student's own repeat, not adapted from the lesson.Fifty saved prompts, none reusable. Fewer and better is the assignment.
8Capstone: the week's log (failures required) + the one-page playbook, presented in five minutes.The log shows kept/fixed/thrown-out verdicts; the playbook is in the student's voice and specific to their week. The playbook is the course grade.Spotless logs. A week of real use produces throwaways — no failures means light use or no scrutiny.

Course 7 — Build a Tiny Language Model: turn-ins and rubric

LessonTurn-inWhat "good" looks likeWatch for
1Model card v1: data seen, capabilities, three right predictions, one funny wrong one.The wrong prediction is explained by the counts, not just laughed at.Cards that claim the model "understands" anything. It counts.
2Twenty generated lines; three most English-looking + the strangest, each tied to specific counts.The explanations reference actual table rows ("q always finds u because...").Picks justified by vibes with no counts named.
3Nine labeled lines at T = 0.2 / 1.0 / 2.5, plus the math-homework answer.The labels describe character honestly; the homework answer picks low T and says why.Students who never found their machine's greedy loop — it's the point of the lesson.
4The wall table: possible rows vs rows seen for k = 1–4, favorite line each, two closing sentences.The "about to become impossible" sentence names sparsity, not just size.Tables copied without the coverage percentages computed.
5Training report: 50 vs 500 rounds — final losses, one line each, where improvement stops and why.The "why it stops" answer connects to one-letter context, not magic.Confusing a low loss with a good writer. This model tops out at lesson-2 quality — that's the insight.
6Three tokenizations (plain sentence, own name, "strawberry") with counts and surprises.The closing sentence connects chunks to letter-miscounting mechanically.Students reading the splits as errors. The splits are the lesson.
7Diet report: one line per corpus, a voice difference, a unique learning, a shared blind spot, the internet-scale sentence.The blind-spot observation is verifiable in the tables (a pair with zero odds).Blind spots stated without checking the counts.
8Capstone: corpus description, generated page with best/worst marked, model card, 3-minute presentation.Corpus follows the rule (own words or public domain); the card names a "belief" traceable to the corpus. The card is the course grade.Group-chat corpora (not only their words) and copyrighted text. Check the corpus description first.

Course 9 — Research Agents: turn-ins and rubric

1An agent-run transcript annotated M (model) or C (code) per line, plus two sentences on why the dispatch table matters.Every line correctly attributed; the two sentences name a concrete risk of models executing directly.Confusion between the model requesting an action and the code running it — that boundary is the lesson.
2A designed tool set for a real task: each tool's name, job sentence, and arguments — plus the deliberately withheld tool with the reason.The withheld tool has a thoughtful reason (irreversible, private, costly), not just "didn't need it."Tool sets that include send-money or delete-anything without noticing what they granted.
3Two real questions decomposed by hand AND by the model, with comparison sentences.The comparison finds at least one angle each side missed — evidence of actually reading both lists.Angles that are synonyms of each other. Each angle should aim at a different part of the answer.
4Three notes traced to their exact source sentences, plus the note whose page says something slightly different.The mismatch found (the dated plot counts) and stated precisely.Notes cited to the wrong page — the receipts are the deliverable; check one at random.
5The claim table marked backed / stretched / unbacked, with the stretch explained.The stretch caught: a real quote whose claim quietly says more (the budget claim).All claims marked "backed." The table contains a seeded stretch; an audit that finds nothing wasn't run.
6Break-the-verifier: a planted wrong fact, rerun verdicts, three sentences on why it was caught or missed.The explanation connects to source counting — a lie nothing contradicts survives, and the student says so.Students grading the verifier as "worked" without checking the quarantine reasons.
7The number-to-row list for the full report, plus the sentence they'd cut and why.Every report number traced; the cut choice defended by confidence or relevance, not length.Numbers "traced" to the report itself rather than to claim rows.
8Capstone: cited report with Limits, claim table, quarantine, run report with a trust paragraph; 5-minute presentation.Privacy answered first; the trust paragraph distinguishes what they'd repeat from what they'd verify by hand.Reports with uncited numbers, and questions about private individuals. And check the privacy answers first.

The AI tool itself

Lessons say "the AI chatbot your class uses" deliberately — the material is tool-agnostic. Pick one chatbot for the class, confirm it's allowed for your students' ages under school policy, and use it consistently so experiment results are comparable. Where a lesson's famous demo now succeeds (letter counting, hallucination traps on well-documented topics), the lessons include escalation paths — treat a passed demo as a teaching moment about mitigation, not a broken lesson.
