3 · Read & play

The gate

Everything upstream can lie to you politely: OCR swaps characters, rules match the wrong thing, LLMs invent. The validate stage is the gate where lying stops, and it runs four kinds of check on every row:

Type checks — is the date a real date, the amount a number? $l,847 fails here, caught at last.
Range checks — is it plausible? A pantry serving 21,200 families in a month didn't; someone's comma moved.
Required fields — a row with no date can't join a table sorted by time.
Cross-checks — do fields agree? Sixty-three donations totaling $0.00 is a contradiction wearing a straight face.

A failing row is not deleted — deletion hides problems. It goes to quarantine with its reason attached: the row, the check it failed, the document it came from. Quarantine is a to-do list for human eyes, and it's where the interesting discoveries live — half the time a quarantined row means the document itself has a story.

Then the two numbers that make you credible. The error rate: what fraction of rows failed validation — measured, not guessed, and reported with the table ("214 rows, 9 quarantined, 4.2%"). And the spot-check: pull five random rows that PASSED and verify them against the original documents by hand, because a gate only catches what it was built to catch. A table with a measured error rate and a passed spot-check is data. Anything else is a rumor with columns.
