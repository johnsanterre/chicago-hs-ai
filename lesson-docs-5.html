3 · Read & play

The other extractor

Lesson 4 ended at the boundary: "we raised around two grand at youth night." No pattern matches that — but an LLM reads it fine, because an LLM matches meaning, not shape. So the varied end of the pile goes to a second extractor, and you already know its habits if you've met the Build with LLMs course; if not, everything you need is here.

The schema prompt. You don't ask "what does this say?" — you ask for exactly the row you want: "Extract as JSON with keys date, amount, families, contact. Use null for anything not stated. Reply with ONLY the JSON object." The schema is the contract; every document gets the same one, so every answer lands in the same table.

The retry pattern. Models sometimes wrap JSON in chatter. Professionals parse, catch the failure, and re-ask — a five-line loop, not a crisis.

The two-sided trade, stated honestly. Rules never invent — they can only find what's literally there — but they quit the moment format varies. LLMs never quit — they'll return a confident row for anything — but they can invent: a plausible date that isn't in the document, "about two grand" recorded as exactly 2000. Neither extractor is trustworthy alone. Rules where format is fixed, LLM where it varies, and every row from either one goes through validation — which is the whole next lesson.

No class API key? The notebook shows every model response precomputed, so the pattern is fully learnable without one — you just won't be able to point it at new documents until a key exists.
