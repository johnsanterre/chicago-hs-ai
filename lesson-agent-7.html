3 · Read & play

Writing from the table only

The last stage is the one readers see, and it is mostly discipline about who does what.

Code merges and ranks. Different angles produced overlapping claims — "60 plots (census)" and "now 60 plots (news)" are one fact, and the merge folds them into one claim with two supporting sources, which is stronger than either alone. Then the claims sort by confidence: confirmed first, plausible after, refuted nowhere — the quarantine file lists those, with reasons, for anyone who asks.

The model writes prose — from the table and nothing else. The writing prompt is strict: use only these claims; cite the source after every factual sentence; hedge anything labeled plausible ("a single source suggests\u2026"); if the claims don't answer part of the question, say so. The model turns rows into readable paragraphs, which it is good at. It does not get to add facts, remember things, or round numbers — everything factual traces to a row, and every row traces to a quote, and every quote to a URL. You built that chain across four lessons; the report is just the chain made readable.

The limits section is not optional. "No source states the garden's budget; the lease claim rests on one page" — two sentences like that do more for the report's credibility than any amount of confident prose, because they prove somebody checked. A report that admits what it doesn't know earns trust for what it does say. The figure makes the point physically.

5 · Quick check

Check yourself

6 · Build

The number diff

Run the notebook's final check by hand: list every number that appears in the generated report, and for each one find its row in the claim table. A number with no row is an invention that slipped through — the notebook's report has none, but your capstone report might, and this diff is how you'll know.

Turn-in: the number-to-row list, plus one sentence: which sentence of the report would you cut if you could only keep half of it, and why.
