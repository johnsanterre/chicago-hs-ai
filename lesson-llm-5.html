3 · Read

Stateless, and honest about it

The API is stateless: every call stands alone, no memory of the last. A "conversation" is your code re-sending the entire history each turn — the very fact you learned in How AI Works lesson 1, now load-bearing in your own code.

The whole app is three parts. The history list of {'role': …, 'content': …} dictionaries — the complete memory, owned by you. The turn function: append the user message, send the full list, append the reply, return it. The loop: input(), chat_turn(), print, repeat. Fifteen lines and it works, and you understand every one of them.

The economics follow from the design: re-sending history means each turn costs slightly more than the last, which is why production chat apps trim, summarize, or window their histories. Your build adds the first version of that discipline — a guard that warns when the list is getting long. Small program; real-world shape.
